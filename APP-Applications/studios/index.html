Suite nLab

Un même esprit d’interface pour les outils nLab.

PDF, JSON, code et image partagent une logique commune : menus simples, ruban contextuel, traitement local par défaut, export explicite et séparation stricte entre code public et données privées.

Principe

Public d’abord, privé en surcouche

Les applications restent utilisables sans compte. Une future connexion privée pourra charger des données autorisées depuis Google Drive sans les incorporer au build public.

Les modules d’authentification/RBAC/rate-limit existent dans le framework mais ne sont pas encore tous promus comme stables.

Mode privé cible

Connexion Google / Drive

  • session applicative opaque et courte ;
  • RBAC côté serveur, deny-by-default ;
  • quota/rate-limit avant les appels Drive ;
  • données privées chargées seulement après autorisation ;
  • aucun secret dans GitHub Pages.
Règle de sécurité

Pas de faux “privé” côté client

Masquer un bouton ou un panneau dans le navigateur n’est pas une autorisation. La future couche privée doit être servie par le gateway nLab et contrôlée côté serveur avant toute lecture ou écriture Drive.
